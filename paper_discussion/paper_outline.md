# ヒューマンインタフェース学会 論文構成案：学長AIにおけるマルチエージェント並行処理と動的フィラー生成の有用性

## 1. はじめに（Introduction）
- **背景:** 大規模言語モデル（LLM）を用いた対話AIシステムの普及。特に大学の「学長AI」のようなペルソナを持つシステムでは、権威ある振る舞いと同時に、ユーザーを待たせない自然な対話テンポが求められる。
- **課題:** RAG（検索拡張生成）や複雑な推論を伴う場合、システムが応答を開始するまでの体感待ち時間（TTFA: Time To First Audio、ユーザーの耳に最初の音声が届くまでの時間）が長くなり、対話のテンポが損なわれる。
- **提案:** 意図分類、フィラー（相槌）生成、メイン応答生成を独立したエージェントとしてマルチエージェント化し、並行処理するアーキテクチャを提案する。

## 2. 提案システム：マルチエージェント並行処理アーキテクチャ
- **システム構成（`ResponseOrchestrator` の実装に基づく）:**
  - **意図分類エージェント (Classifier):** ユーザー発話が日常対話かRAG検索を要するかを判定。
  - **フィラー生成エージェント:** ユーザー発話の文脈とペルソナ（学長）に合わせた相槌を即座に生成。
  - **メイン応答生成エージェント:** RAGまたは日常対話エンジンを用いて本回答を生成。
- **動的制御の仕組み:**
  - ユーザーの発話直後、上記3エージェントを並行して起動。
  - メイン応答の最初のトークン生成が**0.5秒**以内に開始できる場合はフィラーをスキップし、そのまま回答を出力。
  - この「0.5秒」という待機閾値は、「システムとの対話において応答遅延が0.8秒以内であれば人間は違和感を抱きにくい」という先行研究の知見に基づいている。本システムのTTS（音声合成）処理にかかる平均時間（約300ms）を考慮し、ユーザーに0.8秒以内に最初の音声（TTFA）を届けるための逆算値として設定された。
  - メイン応答の生成に時間がかかる場合のみ、先行して生成されたフィラーをストリーミング出力し、待ち時間（沈黙）を埋める。

## 3. 評価実験
現状のベンチマークテスト結果（全100問: 10カテゴリ×各10件）に基づく定量・定性評価。

### 3.1 定量評価：応答レイテンシ（TTFA/TTFT）の削減効果
- **目的:** フィラーの有無がユーザーの体感システム遅延（TTFA）に与える影響を検証。統計的有意性を示すため、対応のないt検定（またはMann-Whitney U検定）を実施する。また、音声合成の処理時間を除外した純粋なLLMの応答性能として、TTFT（Time To First Token：最初の文字が出るまでの時間）および、最初の文章が完成するまでの時間も併せて計測・比較する。
- **結果:**
  - **全体平均:** フィラーなしからフィラーありへと、TTFAの大幅な短縮を達成（p < 0.05 等の有意差を明記）。
  - **タスク別効果:**
    - `rag_search`（RAG検索）: 高遅延タスクにおける顕著な短縮効果
    - `complex_consult` / `cross_domain_complex`（複雑な相談）: 推論やツール利用を伴うタスクでの短縮効果
    - `greeting` / `simple_chat`（挨拶・単純対話）: フィラーを必要としない迅速な応答の維持
- **考察:** RAGなどの重い処理を伴うタスクほど、並行生成されたフィラーによる沈黙隠蔽効果が高く、対話のテンポ改善に大きく寄与している。

### 3.2 定性評価：動的フィラーと定型フィラーの品質比較
- **目的:** LLM-as-a-Judge（GPT-4o）を用い、LLMによる「動的フィラー」が、ルールベースの「定型フィラー（固定フレーズ）」と比較して、対話として適切か、学長ペルソナを損なっていないかを評価する。
- **結果（5段階評価の平均スコア等）:**
  - **文脈的適切さ (Appropriateness):** 定型フィラーに対し、動的フィラーが有意に高いスコアを記録。（ユーザーの意図を汲んだ的確な相槌）
  - **ペルソナ一貫性 (Persona Consistency):** 4.74等 （学長としての威厳や丁寧さの維持）
  - **接続のスムーズさ (Smoothness):** （フィラーからメイン応答への自然な遷移）
  - **自然さ (Naturalness):** （機械的・テンプレ的な印象の有無）
- **考察:** マルチエージェント化により、毎回同じ固定の相槌（定型フィラー）を返す不自然さを解消した。メイン応答の計算リソースを奪うことなく、ユーザーの発話に合わせた極めて高い文脈的適切さとペルソナ一貫性を保った相槌を生成できている。

### 3.3 ベースライン（単一LLMモデル）との比較（重要・推奨）
- **目的:** なぜわざわざマルチエージェント化したのか？という学会における根源的な問いに答えるため、単一のLLMプロンプトのみで「相槌＋本回答」を出力させた場合との比較を行う。
- **仮説:** 単一LLMで一括処理（「まず相槌を打ち、その後検索して回答して」と指示）した場合、以下の問題が生じると推測される。
  1. **レイテンシの悪化:** RAGの検索完了や、長いコンテキストの処理を待ってから最初のトークン（相槌）が生成され始めるため、TTFTが改善されない。
  2. **プロンプト肥大化による品質低下:** 「学長としての相槌の打ち方」「RAGの情報に基づく回答の仕方」「意図分類」を全て1つのプロンプトで指示すると指示の競合が起き、ペルソナの一貫性が崩れる、あるいは回答精度が落ちるリスクがある。
- **検証方法:** 提案手法（マルチエージェント並行）と、ベースライン（単一プロンプト処理）とで、メイン回答の応答完了までの総時間（TTCR）と前述の品質スコアを比較。
- **期待される結論:** マルチエージェント化による「責務の分割」と「並行処理」が、応答速度（レイテンシ）と応答品質（ペルソナ維持・正確性）のトレードオフを解消する**有効なアプローチの一つである**。

## 4. 考察（Discussion）
- **マルチエージェント化の利点:** 単一のプロンプトで「相槌と回答を同時に生成して」と指示するよりも、タスクを分割して並列化することで、TTFAの最適化と出力品質（ペルソナ維持・文脈把握）の両立が可能になった。
- **動的スキップの有用性:** 挨拶（Greeting）など軽量な応答時にはフィラー発火率が0%となっており、不必要な相槌による冗長化を防ぐ制御が正しく機能している。

## 5. 結論と今後の展望
- マルチエージェント並行処理による動的フィラー生成が、ペルソナ型AIの体感応答速度と対話品質の向上に極めて有効であることを示した。
- 今後の課題としては、より多様な対話状況における「自然さ(Naturalness)」のさらなる向上や、音声対話システムへの統合時の音響的フィラー（「えーと」「その」などの息継ぎ）とのハイブリッド化などが挙げられる。
