# ユーザー向けのモデル・推論設定

会話画面の設定から変更し、次の送信に適用する。設定はブラウザの会話画面が保持し、各リクエストに添付する。サーバー全体のモデル設定や、別の利用者の選択を変更しない。

## 設定の適用先

| 設定 | 適用先 |
| --- | --- |
| メインLLM | 親の会話Agent。専門Agent・RAG回答・意図分類のモデルは変更しない |
| 動的フィラーLLM | 外部動的フィラーの生成 |
| 温度・最大トークン数 | 親の会話AgentとRAG回答。未指定時は既定値を維持 |
| RAG Top-k・スコア閾値 | 学内検索へ振り分けられた会話の検索処理 |
| TTS話者 | そのリクエストの音声と口形列の生成 |
| 音声入力 | ブラウザ認識、またはサーバーに配置済みのWhisperモデル |

温度の設定は対応するモデルのみ利用できる。初期候補のGPT-4o／GPT-4o-miniでは指定でき、GPT-5.2ではモデル既定を使用する。設定画面に表示する候補・上限・話者・音声認識モデルは `GET /api/text-chat/settings` から取得する。

最大トークン数は親AgentのResponses APIに合わせて16〜4096を指定できる。空欄の場合は既存の既定値を使用する。

LLM候補は `GAKUCHO_LLM_MODELS`、動的フィラー候補は `GAKUCHO_FILLER_MODELS` のカンマ区切りで構成できる。既定のGPT-5.2は維持される。モデル名を追加する場合は利用先アカウントでの対応を確認する。2026-11-24の実装確認では、既存アカウントのモデル一覧にGPT-4o／GPT-4o-mini／GPT-5.2が存在することを確認した。モデル一覧の確認は、全候補で実際の文章生成を検証したことを意味しない。

## モード

- **学長モード** (`general`): 既存の学長との対話。学内検索・専門Agentを利用する。
- **一般AIモード** (`assistant`): 学長を名乗らない一般アシスタント。学内検索・学長用専門Agent・外部フィラーを使用しない。
- **式典モード** (`ceremony`): 既存の学長による式典向けの簡潔な応答。

既存の `general` を中立AIへ置き換えず、従来の学長対話を維持している。

## TTS話者

読み込んだStyle-Bert-VITS2モデルの話者一覧から選ぶ。モデルが単一話者なら選択肢も一つだけとなる。架空の話者や未配置モデルは追加しない。指定された話者IDは音声生成と同じ推論から得る口形列に使用し、共有モデルの話者設定を書き換えない。

## サーバー音声認識の準備

ブラウザ音声認識は従来の方法を使用する。Whisperを利用する場合は、運用環境側で以下を準備する。

1. `openai-whisper` と `ffmpeg` を利用できるようにする。
2. 利用を許可するモデルを `WHISPER_MODELS` にカンマ区切りで設定する。既定は `base,large-v3-turbo`。
3. 対応するチェックポイント（例: `base.pt`）を `WHISPER_CACHE_DIR` に配置する。既定は実行ユーザーのキャッシュディレクトリ配下の `whisper`。コンテナ運用ではこのディレクトリを明示的にマウントする。
4. `WHISPER_DEVICE` を必要に応じて設定する。既定は `cpu`。

このPRによる本番環境の変更やモデル取得は行わない。設定一覧の取得や未準備モデルの選択によって、モデルを自動ダウンロードすることはない。準備できていない選択肢は理由とともに無効表示する。

Whisper録音は `POST /api/speech/transcribe` へ `file` と `model` をmultipartで送る。nginxはこのアップロード経路のみ9 MiB（multipartの付加分込み）まで転送し、アプリ側では録音ファイルの8 MiB・60秒を上限とし、同時に処理できる録音は一件。ブラウザではタイマー遅延を考慮して59秒で自動停止する。処理中の場合は429、未準備の場合は503で返す。ブラウザ側では録音の中止・設定の切替・会話リセット・画面終了時にマイクと通信を解放し、古い認識結果を後から送信しない。

## 検証の対象

外部LLM・実DBへ接続しないテストで、値の検証、UIからのパラメータ送信、推論への引渡し、同時リクエスト間の分離、音声モデルの選択と未準備時の扱いを確認する。モデルの品質評価や本番でのマイク入力は別の運用確認となる。

画像機能と画像モデル選択はIssue #167に分離し、この設定機能には含めない。

## 空欄時の値と表示

温度に対応する会話AIはResponses APIの初期値1.0、学内検索の回答はRAGModuleの0.7を使用する。温度非対応モデルには「変更不可」と表示する。会話AIの最大トークン数はアプリから指定していないため、数値の既定値があるようには表示しない。学内検索の回答は200トークン。Top-kは5件、閾値は0.25が初期値となる。

画面には処理別の空欄時の値・設定範囲・入力例を表示する。入力例は既定値ではなく、利用者が調整を始めるための目安。表示改善によって実際の推論設定や空欄時の送信内容は変更しない。

会話AIの温度の根拠: [Responses API仕様](https://developers.openai.com/api/reference/resources/responses/methods/create)。学内検索の値は `backend/app/agent/modules/rag_module.py` の初期値に基づく。
